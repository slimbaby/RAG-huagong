## 反思能力（Reflexion）落点 3+4 实现
- 讨论「项目里哪些地方能加反思学习」，定位 4 个落点：① 检索级反思（扩展 evidence_judge）② 答案级自评（新增 self_critique 节点，注意流式下答案已吐出的冲突）③ 教训入库（lesson 类型记忆）④ 离线批量反思（评测低分样本归因）。
- 关键设计决策：教训与长期记忆**分属不同语义位**——教训是「行为准则」，长期记忆是「事实/背景」，必须在 prompt 中独立成段（`## 历史教训`），否则 LLM 会把教训当依据引用，削弱「严格基于参考资料回答」约束。
- 两类 lesson 分级：系统级（scope=`__system__`，来自落点4 评测归因，每次无条件注入，走 `get_system_lessons()` 而非语义召回——因为它记的是系统术语，与用户提问语义距离远召不回来）+ 会话级（scope=真实 session，落点3 自评失败产生，按会话召回）。
- **用户三项决策**：① prompt 占位符用 `format_map` + 默认值字典做向后兼容 ② 暂不给 memory_extractor 加 "lesson" 类型白名单（避免教训混进事实语义位）③ LessonStore 放 deps 共享实例。

### 【生产事故】uv.lock 缺 asyncpg / tabulate
- **根因**：`uv.lock` 过期于 `pyproject.toml`——pyproject 声明了 44 个主依赖，uv.lock 只收录了其中 42 个，缺 `asyncpg>=0.29.0` 和 `tabulate>=0.9.0`。
- **影响**：`Dockerfile:22` 用 `uv sync --no-dev` 构建生产镜像，装出的环境 `import asyncpg` 直接 ModuleNotFoundError → `app/core/database.py`、`app/api/auth.py` 启动即崩。已用 `uv sync --frozen --no-dev` 完整复现。
- **修复**：`uv lock` 重新生成锁文件（已备份原文件到临时目录）。结果：新增 2 包、移除 0、**版本变化 0**（langgraph 1.2.11 / langchain-core 1.5.6 / fastapi 0.141.1 等全部未漂移）。uv.lock 大量行 diff 仅为文件重排，语义等价。
- **验证**：重新模拟生产构建，`import asyncpg` + `import app.core.database` 均通过。

### 【代码缺陷 1】reflector 字段名不匹配（严重）
- `app/evaluation/reflector.py` 的 `_get_score` 映射表写的是 `"judge"` / `"citation"`，但 `CaseResult` 真实字段是 `judge_score` / `citation_score` → `getattr` 取不到 → **静默返回 0.0** → 所有 case 被误判为「完整度/引用不达标」，归因维度全错。
- 之所以第一轮没发现：当时的测试用例用了自定义 `Case` 类，字段名恰好写对，掩盖了 bug。
- 修复：映射表改为 `judge_score` / `citation_score`；同时把维度定义从「完整」改为「质量」——CaseResult 无独立 completeness 字段，judge_score 是 LLM-as-Judge 六维加权总分（含 completeness/accuracy/clarity），标成「完整」语义失真。

### 【代码缺陷 2】LessonStore 排序键自我漂移
- `get_session_lessons` 用 `last_accessed` 排序，但 `last_accessed` 在召回时被自己更新 → 排序依据随读取动作漂移，且 `access_count` 从不持久化（重启即丢）。
- 修复：排序键改为稳定的 `(confidence × importance, created_at)`；新增 `_touch()` 统一更新访问计数并落盘。

### 【代码缺陷 3】持久化非原子 + 损坏行导致整体加载失败
- `_persist` 直接覆写目标文件，进程中途崩溃会留下半截 JSONL；`_load` 遇单行损坏 JSON 直接抛异常导致全部教训加载失败。
- 修复：改为「写 `.tmp` + `os.replace`」原子替换；`_load` 逐行 try/except，损坏行跳过并计数，不影响其余记录。
