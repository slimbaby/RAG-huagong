## 追加（10:15）：回答「能否直接在 RAG 对话里让 AI 帮我申请入园」→ 补跑新链路真实模型回归

**背景**：用户问现在能否直接在前端对话里沟通办理入园申请。上一轮交付时把「新 `_generate_flow()` 链路未跑真实 DeepSeek」列为边界项，因此先实测再回答，不凭代码推断。

**实测（demo_driver + DeepSeek v4-pro，非流式 `/api/chat/query`）**：
- 明确办理句（含 13 字段原文，8–14s）：`flow_id=driver_entry`、`flow_action=action`、`definition_version=1`，抽出全部 13 字段，一次性追问 5 类缺件，`complete=false`（正确，附件未齐）。
- 同会话改字段（「性别男，公司名称改成某某化工」）：仍留在通用流程，槽位合并正确，模型明确说「由您本人在确认卡里点击提交，我不会代替提交」。
- 歧义句「能帮我办理入园吗？」：0.0s 短路 `intent_choice` 候选卡，不调模型不检索。
- 上传 5 类附件后说「都上传好了，核对一下」：`get_my_attachments` 自动关联 5 个显式 ID → `complete=true` → 确认卡 3 分组 / 5 附件 / 标题「入园申请信息核对」，身份证与手机号在卡里已打码；`slots` 保留原值仅供表单预填。
- **全程零写库**：`flow_applications=0`、`flow_attachments=0`。

**结论**：可以。链路为「对话抽字段/追问 → 上传 5 类证件 → 确认卡 → 点『去表单核对并提交』 → 本人提交 → admin 审核」，AI 不写库、不审批。**操作提醒**：纯陈述句（「我拉了一车甲醇到门口了」「明天上午八点我到门口」）仍会被当知识库问答，需说「帮我申请入园…」或点输入框 AI 快捷按钮；前端确认卡按钮文案是「去表单核对并提交」，不是直接提交。

**环境清理**：2 个临时验证脚本已删；上传的 5 张附件记录与容器文件已删；Redis 中 4 个 `session:flow-verify*` 键已删（需要 `redis-cli -a $REDIS_PASSWORD --no-auth-warning`，无密码会报 NOAUTH）；最终 `flow_applications=0` / `flow_attachments=0` / Redis dbsize=0。

## 追加（10:30）：修复「上传图片后新开会话、之前填的信息全没了」

**用户现场**：在对话里按 AI 提示逐轮填了姓名/性别/身份证/手机号，上传 5 张证件图片后，界面跳到一个空的新会话，AI 回「五类证件都齐了，不过信息还差不少，先把姓名/性别/…发我」。

**还原证据**（只读）：Redis 有两个会话——`session:entry-1795596417315_h9n121k9q:*`（旧，聊天历史里能看到用户第二轮给的姓名等 4 项，AI 正在追问车牌）和 `session:flow-1795659451314_72keqfpeh:*`（新，创建时间正好等于日志 02:17:31 第一张图片上传时刻，历史里只有「图片都上传完毕了」+ AI 重新要基础信息）。DB 里 5 张 `flow_attachments` 均属 demo_driver 且 `application_id` 为空（未绑定，可复用）。

**根因**：`frontend/src/stores/chatStore.ts` 的 `setFlowAttachment()` 在「当前会话 ID 不是 `flow-` 前缀 或 activeFlowId 不匹配」时调用 `startFlowSession()`；而 `startFlowSession()` 无条件把 `flowSlots` / `messages` / `definitionVersion` 清零。`flowSlots` 是按 `sessionId` 存 localStorage 的，切会话后旧字段读不到，只剩刚上传的附件 ID → 用户看到"信息都没了"。用户当时在 `entry-` 前缀的老会话里，必然命中该分支。

**修复（纯前端，3 处）**：
1. `setFlowAttachment()` 不再新建会话，只在当前会话累加附件 ID、保留全部已有字段与版本（上传是补充信息，不是开始新流程）。
2. `startFlowSession()` 新建独立会话时，若**同一流程**（`activeFlowId === flowId`，或当前未标记流程但已有槽位）则把 `flowSlots` / `definitionVersion` / `flowPayload` 带到新会话；切到**别的流程**或空白会话才清空。保留「隔离聊天历史与长期记忆」的原设计意图。
3. `switchSession()` 在同流程会话间切换时合并已上传但未绑定的附件 ID（目标会话已有值优先），避免恢复时要求重传、也不依赖模型主动调 `get_my_attachments`；不同流程一律不带。

**回归测试**：`frontend/src/stores/__tests__/entryIntentChoice.test.ts` 从 6 项扩到 13 项，新增：上传不改会话 ID / 字段与版本与附件全在、连续 5 类附件只累加、同流程切会话带走字段、切别的流程清空、候选卡办理后新会话仍带完整 `flow_slots`、切回原会话合并附件、跨流程不带附件。

**给用户的恢复路径**（不改其浏览器 localStorage）：刷新页面让 HMR 生效 → 在会话列表点回上一个会话（标题约「你好，帮我申请入园」）→ 已填的 4 项与 5 张附件都还在 → 继续补齐车牌/车辆/公司/化学品/重量/时间 → 出确认卡。前端容器 `frontend -> /app (rw)` 且跑 `npm run dev`，源码改动会 HMR，无需重启容器。

**顺带发现的遗留（未改，已告知）**：配置 `session.session_prefix = "entry-"`，前端 `FLOW_SESSION_PREFIX = 'flow-'`，两者不一致；因前端每轮都带 `flow_id`，后端会话前缀兜底实际用不到，功能不受影响，但配置化语义不彻底，建议后续统一（需同步改测试断言）。
