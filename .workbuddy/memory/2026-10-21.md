## 固定流程（Workflow）模块 —— 第 1/2 期落地

### 背景与决策
- 需求：把"公司固定流程"接入 RAG 项目。
- 讨论后确认的需求画像：**生产工单/采购下单流** + **需要人工卡点** + **流程多且经常调整** + **要写公司 PostgreSQL** + **要发企微/邮件通知**。
- 由此定下技术形态：**YAML 声明流程骨架 + Python 只实现节点 handler**（`side_effect` / `notify` 两类需写代码，其余通用）。理由：流程多且常改 → 骨架必须改配置不改代码；写库/通知有复杂逻辑 → 逃不掉 Python。
- 决定 workflow 走**独立 API**（`/api/workflows/*`），不塞进 `/chat/query` —— 后者是无状态问答，前者是跨请求长事务。

### 关键决策：删除自研 Checkpointer 而非改造
- 查证 `app/tracing/checkpointer.py`（178 行）：**零调用点**（全项目无任何代码读 `deps["checkpointer"]`）、`app/api/checkpoints.py` 全是 404 空壳、前端零调用。
- 而它想干的活 tracer 已做得更好（它的 `duration_ms` 写死 0、无父子层级、无前端消费）。
- 结论：LangGraph 官方 checkpointer 负责它不可替代的职责（驱动图恢复执行），tracer 负责执行历史审计，两者分工不重叠 → **删掉自研的**。
- 选 `AsyncSqliteSaver` 而非 `SqliteSaver`：后者是同步 `sqlite3`，在 FastAPI async 事件循环里会阻塞 worker。

### 实现要点（踩过的坑）
1. **`GraphInterrupt` 继承自 `Exception`**，会被 `except Exception` 吞掉导致"挂起变失败"。引擎里定义 `_CONTROL_FLOW_EXCEPTIONS` 显式 re-raise。
2. **`slot_extract` 必须拆成两个节点**（抽取节点 + `__gate` 闸门节点）。若在同一节点里 interrupt，恢复时该节点从头重放 → LLM 被重复调用。拆开后闸门只做纯判断。
3. **`human_approval` 不在 `GENERIC_NODES` 表里**，判断顺序必须是"先判类型再查表"，否则报"未知节点类型"。
4. **`end` 类型节点不能串在线性主链上**，否则 `reject` 会在校验通过后也被执行。实现为"主链 = 排除 end 的步骤"，end 只能被 `goto`/`on_fail` 到达；主链末尾指向 `primary_end`（优先 id 为 `done` 的）。
5. **`rule_check` 失败时必须同时写 `status` + `error`**，否则后续 `end` 节点会把 failed 覆盖成 completed。
6. **checkpointer 单例不能按路径切换**：切换时 close 旧连接，已编译的 graph 仍持有它 → ainvoke 卡死。最终改为路径无关的单例 + 关闭只在应用 shutdown。
7. **aiosqlite 每个连接起一个后台线程**，pytest 退出时线程不结束会挂住整个测试进程。测试用 `pytest_asyncio.fixture` 在用例后 `close_checkpointer()`。
8. **`app/api/workflows.py` 的相对导入**：`.checkpointer` 会被解析到 `app.api.checkpointer`（同名文件），必须用 `..workflows.checkpointer` 绝对路径。

## 复查修复（第 2 期）—— 提交 059e66a

复查上一轮 23 文件的改动，发现 3 个真实缺陷，全部已修 + 补回归测试。

### 坑 9：多轮补充槽位时已补值丢失（严重）
- **现象**：两个必填槽位 a/b，补 a 后 checkpoint 里`slots` 仍为 `{}`，第二次追问只剩 b（且 a 又被问了一遍）。
- **根因**：LangGraph 官方文档明确 "The graph resumes from the start of the node, **re-executing all logic**"。我原先在闸门节点里用 `while True` 多次 `interrupt()`，恢复时中间状态不写回 state。
- **踩坑过程**：先试「自环 + 节点内循环」→ `GraphRecursionError`；再试「单次 interrupt + 边路由」→ 验证通过。
- **修法**：闸门改为**单次 interrupt + `add_conditional_edges` 边路由**。节点返回 `_gate_retry: bool`，router 据此回到闸门或走向后继。
- **附带坑**：放行时必须**显式写 `_gate_retry=False`**，否则 state 里上一轮的 True 会残留 → 原地死循环。

### 坑 10：`graph.aget_list()` 不存在
- 正确 API 是 `checkpointer.alist(config, filter=, before=, limit=)`，返回 `AsyncIterator[CheckpointTuple]`。
- **但 `alist` 不支持 `thread_id="*"` 通配** —— `search_where()` 生成的 SQL 是 `thread_id = ?` 精确匹配，传 `"*"` 只会去查名为 `*` 的线程。
- **修法**：新增 `list_thread_checkpoints()`：先 `SELECT thread_id, MAX(checkpoint_id) ... GROUP BY thread_id`拿列表，再逐个 `aget_tuple`。
- **状态位置**：CheckpointTuple 里状态在 `t.checkpoint["channel_values"]`，**不是** `.values`（`.values` 是 StateSnapshot 的属性）。
- **中断位置**：不在 `tasks` 而在 `t.pending_writes` 里 `__interrupt__` 通道的值，形如 `(task_id, '__interrupt__', [Interrupt(value={...})])`。两种形态统一到 `extract_interrupt_payloads()`。
- 另：`aget_state_history` 是**异步生成器**，`await graph.aget_state_history(...)` 会失败，必须 `[h async for h in ...]`。

### 坑 11：闸门重抽取覆盖用户已确认的槽位
- 补槽位时调LLM 再抽一次，模型常复读已确认的旧值（把 amount 999 覆盖掉用户填的 88）。
- **修法**：`_reextract` 加 `filled` 参数，在 prompt 里显式告知「已确认字段不要重复输出/修改」+ 只抽剩余字段；合并时跳过已有值的键。

### 坑 12：`_snapshot` 读不存在的 state 键
- `state.get("__interrupts__")` —— 引擎从不写这个键，导致所有接口返回的 `interrupts` 恒为空。interrupt 本来就不在 state 里，而在 LangGraph 快照结构中。改为调用方显式填充。

### 测试相关
- 全量：`pytest tests/ -q --deselect "tests/test_services.py::test_embedding_service_init"` → **134 passed**。
- ⚠️ deselect 必须是 **nodeid**（`文件::用例名`），写文件路径无效。之前误写 `--deselect tests/test_embedding_service_init.py` 导致全量跑永远挂起，误以为是新引入的问题。
- ⚠️ bash 里 `cmd | tail` 后取 `$?` 拿到的是 `tail` 的退出码，不是 pytest 的。要判断 pytest 是否挂起必须重定向到文件再取 `$?`。
- 测试有效性反证：把 `_gate_retry` 路由改成总是放行，新回归测试如期失败（`仍缺 owner 时应继续挂起追问`），确认测试真的抓得住 bug。

## 甲烷下单流程 + Excel 模拟 ERP（提交 82e0856）

### 业务链路
用户："下一个11.30号发货的体积5吨的甲烷订单"
→ LLM 识别下单意图 → 抽槽位 → 缺客户则追问 → 校验 → **写 ERP 待排产池** → 通知用户
→ （晚上 8 点）定时任务拉 pending 订单按交期排产

### 关键设计决策：workflow 只做「接单并落库」
- **「等 20:00 排产」不做成 workflow 步骤**。LangGraph 的挂起是「等人」不是「等时间」，
  等时间会让流程实例在 checkpoint 里躺十几个小时，服务重启/锁/堆积全出问题。
- 排产是定时任务 `nightly_scheduling()`，建议 APScheduler / cron 每天 20:00 调。

### 防误触发两道闸（误建单代价 >> 漏建单）
1. 工具描述明确排除：「查询订单状态、查库存、问价格等只读请求不要使用本工具」
2. 后置拦截 `_looks_like_read_only()`：命中只读词直接拒绝启动流程

###踩坑
- 坑 13：`_chat_with_tools` 里是 `output = fn(**args)` 同步调用，加 async 工具必须
  改成 `if inspect.iscoroutinefunction(fn): output = await fn(**args)`。
  注意 `asyncio.iscoroutinefunction` 判断已装饰的函数可能失效，用 `inspect.iscoroutinefunction`。
- 坑 14：`interrupts` 不在 `ainvoke` 返回值里，interrupt 载荷要从 `aget_state` 的
  `pending_writes` 取（`extract_interrupt_payloads`）。写成 `result["interrupts"]` 恒为空。
- 坑 15：`handlers/__init__.py` 里 `from ..workflows.nodes import ...` 层级错误
  （handlers 已在 workflows 下，应是 `..nodes`）。此前从未被调用所以没暴露，
  一旦真的调用 register_builtin_handlers 就 ModuleNotFoundError。**零调用点的模块最危险。**
- 坑 16：Excel 落库中英键名不一致 —— 传入 `product` 而取 `order.get("产品")`，
  静默写成 None。约定：接口层统一用英文键，落表时才映射成中文表头。
- 坑 17：全量 pytest 偶发不退出（测试全过但进程挂着）。定位非确定性线程竞态，
  用 `faulthandler.dump_traceback_later(N, exit=True)` 包一层既能自动抓栈又能保证退出。
  跑测试时带上这个，比裸跑稳定。
- 坑 18：同步测试里用 `asyncio.run()` 调 async 函数 —— 万一以后改成
  `@pytest.mark.asyncio` 会撞车。直接标 async 用例更好。

### 日期归一化（业务必需）
`normalize_date()` 把中文相对日期转 YYYY-MM-DD：
「11.30号」「11月30日」「11/30」「下个月底」「本月底」「下个月15号」「下下个月10号」
「明天」「后天」，已过日期视为明年（1.5号 → 2027-01-05），跨年正确（下下个月底 12月基准 → 2027-01-31）。
槽位声明 `type: date` 即自动生效，解析不了的保留原值交给 rule_check 报错。

匹配顺序有坑：必须先判「下下个月」再判「下个月」，否则「下下个月10号」会被
「下个月」先命中变成 11月。

### 排号与幂等
- 单号 `MO{YYYYMMDD}{4位序号}`，按当天已有最大值递增。
- 幂等键 `run_id:step_id`（LangGraph 恢复时节点重入，没幂等键会重复建单）。
- 幂等命中时**不覆盖原记录**，直接返回已有单号。
