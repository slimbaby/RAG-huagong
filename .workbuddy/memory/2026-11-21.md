# 2026-11-21

## 纯前端预览（不启 Docker）
- 结论：前端 `frontend/` 是 Vite + React SPA，宿主机 Node 22 直接 `npm run dev` 即可跑，不需要 Docker；Docker Compose 只是为后端依赖（Milvus / Redis / PostgreSQL / MySQL / ES / MinIO / RAGFlow）+ backend 服务提供运行环境。
- 已在宿主机启动：`npm --prefix frontend run dev -- --host 127.0.0.1`，端口 5173，5 个路由（`/login`、`/`、`/documents`、`/records`、`/evaluation`）均返回 200。
- 坑1：`App.tsx` 的 `RequireAuth` 需要 localStorage 有 `rag_auth_token`，无后端无法登录。已新增 `frontend/public/preview.html` 作为临时 UI 预览入口：写入假 token + 缓存角色后跳 `/`；`authStore.init` 的 `/auth/me` 失败会降级读缓存，因此能进全部页面。该文件仅用于看 UI，可随时删除。
- 坑2：`api/client.ts` 默认 baseURL 是绝对地址 `http://127.0.0.1:8000/api`（除非设 `VITE_API_BASE_URL`），所以 `vite.config.ts` 里的 `/api` proxy target `http://backend:8000` 在宿主机模式下实际不会被用到；若将来设成 `/api`，需把 target 改为 `http://127.0.0.1:8000`（不能硬改，docker 容器内依赖 `backend` 服务名）。
- 各 store（trace/document/eval/chat）fetch 都有 catch，无后端时页面渲染骨架 + 空态，不会白屏。
- `.env` 的 `CORS_ORIGINS` 已同时包含 `http://localhost:5173` 与 `http://127.0.0.1:5173`，将来本地起后端直连无跨域问题。
