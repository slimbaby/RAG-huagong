## 梳理「文档上传 → 切分入库 → 生成评测用例」全流程
输出了一张完整流程图（内联 SVG）+ 逐方法调用链说明。关键结论（供后续接手）：

- 主入口：`backend/app/api/documents.py`
  - `POST /api/documents/upload` → `upload_document()`（:262）→ `background_tasks.add_task(_process_document, ...)`（:340）
  - `_process_document()`（:145）是单一后台协程，串起：解析 → `delete_by_doc_id` → `_index_chunks` → `_save_metadata(ready)` → `_generate_eval_cases` → 清理 checkpoint
- 解析分支：`config.py` 默认 `RAGFLOW_ENABLED=True`，但 `.env` 覆盖为 `false` → 实际走 `_parse_file()` 本地解析；`.json` 强制本地。RAGFlow 分支（`_parse_via_ragflow`）不做 `SmartTextSplitter` 二次切分，本地分支做 `split_by_heading()`。
- 当前 .env：CHUNK_SIZE=512 / CHUNK_OVERLAP=50 / MAX_FILE_SIZE_MB=50；embedding 为本地 `BAAI/bge-base-zh-v1.5`。
- 入库是 Milvus（`document_chunks`，15 字段，HNSW+TRIE）+ BM25 pickle 双写，入口 `HybridMilvusStore.insert()`。
- 评测用例**自动生成**于 `documents._generate_eval_cases()`（:207），输入是内存 chunks（非回查 Milvus）；`EvalCaseGenerator.generate_from_chunks()` 截 8000 字喂 LLM → `add_cases_to_db()` 写 PG `eval_cases`，旧用例先 `mark_stale_by_doc_db`。前端无「生成用例」按钮。

- 用例生成在 `status=ready` 之后，失败仅 warning 不影响文档状态；前端轮询到 ready 时用例可能尚未落库。
