## 新需求讨论：司机入园预约接入 RAG 对话（只做代码盘点 + 方案选型，未改代码）

**代码核实结论（供后续接手）**：
- 全仓库无入园/预约/通行证/司机相关实现（grep 只命中面试文档与评测集）。
- 同构原型已存在：`methane_order` 流程 = 对话识别意图 → `create_order`/`resume_order` FC 工具（workflow_tools.py）→ YAML 流程抽槽 + gate 追问 → rule_check → side_effect 写 ERP → notify。docs/04 §13 记录了 3 轮工具闭环。
- Workflow 引擎：YAML → StateGraph 动态编译，7 类节点（slot_extract / rule_check / branch / human_approval / llm / side_effect / notify / end），`interrupt()` + `Command(resume=)` 挂起恢复，闸门用「单次 interrupt + 边路由 `_gate_retry`」避免多轮补槽丢值，`AsyncSqliteSaver`（单文件，多实例需换 PostgresSaver）。
- 聊天入口 `/api/chat/query|stream` 的 ChatRequest 仅 question/session_id/stream/use_agent；工具循环在 `generate_node._chat_with_tools`（max_rounds=2，tool_registry 默认注入，RAG 图也带工具）；`use_agent` 前端从不传，agent graph 无入口。
- 意图分类 `QueryRewriter._classify_query_intent` 是正则：business_query 只认订单/库存/质检/采购；kb_keywords 含「园区/审批/许可证」，入园请求会被判 kb_query 白跑检索 → 建议事务意图前置闸门。
- 图片链路缺口：documents/upload 白名单无图片且会把文件切片入 Milvus（司机证件绝不能走）；聊天接口/前端无附件上传；`LLMService.generate_with_image` 已支持 image_url base64；`image_processor._describe_with_llm` 把**路径字符串**传给期望 bytes 的 generate_with_image（实际会 TypeError，多模态描述不可用）；PaddleOCR 单例可用。生效模型 PREMIUM/STANDARD 均 mimo-v2.5-pro，视觉能力需验证。
- 安全缺口（上线前必补）：`workflows.py /runs/{id}/resume` 不校验 run 归属；`human_approval` 的 approver_role 只是 payload 展示不鉴权；`permission_service.get_user_role` 对「users 表存在但未分配角色」回落 admin（批量建司机账号若漏配角色即越权）；`tracer.start_trace` 记录 user_query 原文、span inputs 落 JSONL；`memory_manager.recall()` 的 session_id 参数未参与过滤（全局长期记忆池，PII 有跨会话召回风险）。

**本轮逐条拍板的 Agent 设计结论（纯讨论，未落地、未改代码）**：
1. AI **不写业务表**，只输出结构化字段 JSON。
2. 已抽字段状态**前端持有**，随每轮 chat 请求回传给后端拼进 prompt。
3. 状态丢失（刷新/换设备）时**从聊天历史重抽全量**；不引入 checkpoint。
4. 交互形态：**一次性交材料 + 按需追问，两者都支持**；对话不承担逐字段采集。
5. **单 Agent + 工具循环**，复用现有 RAG 工具的 `_chat_with_tools`；不用多 Agent、不用 workflow 引擎。
6. **前置轻量意图路由**（关键词 + 小模型二分类）命中入园才切 Agent，只读问题留 RAG。
7. 工具边界**仅四件套**：解析材料 / 取本人附件 ID / 规则校验 / 推确认卡，**全无写权限**。
8. 收口条件：**必填字段与 5 类附件齐备才自动出确认卡**，不由模型自由判断。
9. 确认界面：**聊天内确认卡 + 可跳手动申请表单页**细改；提交仍只有手动接口一条路径。
10. **独立 session + driver 角色**，该通道关闭长期记忆抽取、trace 脱敏，避免 PII 跨会话召回。

最终形态：RAG 主链前加意图闸 → 命中则切单 Agent → Agent 只做识别/解析/收口 → 字段送进确认卡或预填表单 → 提交与审核完全走人工与 admin 原有接口。属于「受约束 Agent（guided agent）+ human-in-the-loop」，不是全自主 Agent。
